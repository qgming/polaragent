---
description: 交付前自检：跑真实检查、核对引用点、清理残留，并报告存疑项
---

给当前改动做一次交付前自检。**只做验证与清理，不要顺手加功能。**

## 1. 跑真命令

从 `package.json` 的 scripts / `Makefile` / CI 配置里找出这个仓库**真实存在**的检查命令（测试、类型检查、lint、构建），逐个跑一遍。**不要假设命令名**。跑了什么、输出是什么，原样报出来；红的就是红的，不要绕过。

## 2. 核对改全了没有

- 用旧名字 / 旧签名 / 旧路径全局搜一遍：还有没有漏改的调用点、导入、类型定义、文档、示例、测试夹具。
- 做过重命名或改接口时，这一条尤其重要。

## 3. 清理残留

看 `git status` 与 `git diff`：

- 调试用的 `console.log` / print、临时注释、写了一半的 `TODO` 有没有留下；
- 有没有与本次改动无关的文件被改（误改的要还原）；
- 有没有临时文件、生成物、本地绝对路径混进来；
- 新增的注释是否多余 —— **默认不加注释**，只留"为什么"这类代码本身说不清的。

## 4. 汇报

- 每项检查的真实结果（命令 + 输出要点）；
- 改动文件清单，以及每个文件改了什么；
- **没做的、没验证到的、存疑的**单独列出 —— 不要用"应该没问题"收尾。

有失败项就继续修到全绿；修不了就明确说清为什么修不了。
