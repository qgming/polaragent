只读测绘：把下面这块代码（或整个仓库）搞明白，产出一份**能留给下一个会话看**的理解备忘录。

**全程只读 —— 不要修改任何文件，也不要顺手修你发现的问题。**

## 要回答的问题

1. **入口在哪**：对外暴露的 API / 命令 / 路由 / 事件从哪进，怎么一路走到核心逻辑。
2. **关键模块与数据流**：数据从哪来、经过谁、存到哪、以什么形状存在。
3. **调用方与依赖**：谁在用它（列出文件），它依赖谁；哪些是稳定的公开接口，哪些是内部实现。
4. **既有惯例**：这个区域怎么做事（命名、分层、错误处理、日志、测试写法）—— 新代码要跟随它。
5. **怎么验证**：测试在哪、怎么跑、大致覆盖到什么程度、有没有集成 / 端到端测试。
6. **风险区**：鉴权、计费、数据迁移、并发、缓存、外部依赖 —— 动它们之前必须先看懂什么。
7. **开放问题**：你没看懂、没查到、或觉得可疑的地方，明确写出来。

## 输出要求

- 每条结论后面跟 `文件路径:行号`；**没有出处就别写**（宁可直接写"没查到"）。
- 短段落 + 列表，不要写成长文。
- 最后一节固定是：**「如果我马上要改 X，第一步该看什么」** —— 给 3–5 条最相关的文件与理由。

除非我明确让你写到文件，否则**只在对话里输出**。
