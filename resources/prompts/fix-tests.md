---
description: 跑测试、定位失败、做最小修复，再跑一遍确认
---

修好当前失败的测试。按闭环走，**不要跳步**。

1. **先跑，拿到真实清单**：先跑最相关的文件 / 子集。项目里怎么跑测试，从 `package.json` 的 scripts、README、CI 配置里确认 —— **不要假设命令**。
2. **逐条判断归因**：是**代码真的写错了**，还是**测试本身过时 / 写错了**？先判断是哪一类，再动手，并把判断依据说出来。
3. **最小修复**：只改必要的地方，不顺手重构、不扩大范围。
4. **复跑确认**：贴出真实的通过输出；顺带说明这次改动有没有影响其它测试。

汇报格式：先说结论（修好了 / 没修好 / 修不了），再列每条失败的「原因 → 改动 → 复跑结果」。

## 红线

- 不许把测试改松（放宽断言、加 skip / only、删用例）来"变绿"；测试本身确实错了才能改，且要说明哪里错。
- 不许用 `try/catch` 或重试把失败吞掉。
- 根因不在本次改动范围内（环境缺依赖、网络不通）时，**停下说明并汇报**，不要为了变绿硬凑。
- 同一个失败连续修三次仍不过：停下，汇报已知与未知。
