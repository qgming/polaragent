description: 根据当前改动生成一条提交信息（不执行提交）
---

为当前工作区的改动写一条提交信息。**只输出信息，不要执行 `git commit` / `git push`。**

1. **先看**：`git status` + `git diff`（含新增文件）。确认里面**没有**调试代码、临时文件、无关改动；有的话先用一两句告诉我，我决定是清理还是照原样提交。
2. **标题**：`<type>(<scope>): <一句话>` —— type 从 `feat` / `fix` / `refactor` / `perf` / `docs` / `test` / `chore` / `build` / `ci` 里选；不超过 72 字符；祈使句、结尾不加句号。
3. **正文**：空一行后用要点写**做了什么**与**为什么** —— 重点写为什么，做了什么从 diff 能看出来。
4. **破坏性变更**单独一段 `BREAKING CHANGE:`，说清影响与迁移方式。
5. 如果改动其实包含两件不相关的事，指出来并建议拆成两次提交（各自给一份信息草案）。
