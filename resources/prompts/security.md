对下面这个范围做一次安全审计（没说范围就是当前改动 / 当前目录）。

**只审计、不改代码**（我说"修"再修）。

## 检查清单（逐项过，不适用的直接跳过）

- **输入处理**：注入（SQL / 命令 / 路径穿越 / 模板 / 反序列化）、未校验的重定向与 URL、XXE、正则灾难性回溯。
- **鉴权与授权**：每个入口是否都校验了身份与权限；有没有越权（拿别人的 id 读别人的数据）、IDOR、把前端校验当后端校验。
- **凭据**：密钥 / 令牌是否硬编码、是否进了日志或错误信息、是否发到前端或提交进仓库、权限是否过大。
- **数据与状态**：敏感数据落盘 / 落日志是否加密或脱敏；并发下的竞态（重复提交、余额类扣减）。
- **外部交互**：SSRF、不受限的文件上传（类型 / 大小 / 路径）、第三方依赖漏洞（看 lockfile 与版本）、回调是否验签。
- **运行时**：CSP / 沙箱 / 权限清单有没有被放宽；`eval`、动态执行、不安全的反序列化。

## 输出格式

按严重度（高 / 中 / 低）分组，每条包含：

1. **问题**：一句话说清是什么漏洞；
2. **位置**：`文件:行号`；
3. **可利用条件**：什么输入、谁能触发、需要什么前提；
4. **后果**：最坏情况是什么；
5. **修复建议**：具体到怎么改（用哪个 API、加什么校验），不要只说"加强校验"；
6. **确认状态**：`已确认`（有证据 / 实际跑通）还是 `怀疑`（代码看着像，没验证）。

**不要报没有利用路径的理论问题，也不要凑数** —— 一条被证实的漏洞比十条猜测有用。确实没发现问题就直说。
