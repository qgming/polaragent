# 开发工具箱

这个插件给你四个**确定性**的小工具。它们都是纯函数：同样的输入永远得到同样的输出，
不联网、不读文件、不执行命令。

## 什么时候该想起它们

| 你要做的事 | 用它 | 不要用它做 |
| --- | --- | --- |
| 校验一段内容有没有被改过 | `hash` | ~~算文件的哈希~~ —— 它算的是**文本**，文件要先 `read` |
| 看清一段 base64 / hex / URL 编码里写了什么 | `encode`（`direction: "decode"`） | ~~解码加密数据~~ —— 编码不是加密 |
| 造测试数据、给临时文件起名 | `uuid` | ~~需要可复现的标识~~ —— 每次调用都不同 |
| 知道今天几号、把时间戳翻成人话 | `time` | ~~时区换算成任意时区~~ —— 只给本地与 UTC |

## 每条的两三个要点

### `hash`

- 默认 `sha256`；另有 `sha512` / `sha1` / `md5`。**新代码不要用 md5 或 sha1**
  （它们只在这两种场合还合适：与既有系统对接、以及非安全用途的内容指纹）。
- 算的是**你给的那串文本**。文件的哈希必须先把文件读进来 —— 而大文件读进来会占满上下文，
  所以"验证一个下载的大文件"这件事，这个工具帮不上，直接告诉用户。

### `encode`

- `format` 三选一：`base64` / `hex` / `url`；`direction` 默认 `encode`。
- **解出来是乱码，说明输入不是那个格式。** base64 解码器不校验输入，
  一段普通文本也能"解"出一串乱码而不报错。看到乱码不要去分析它 ——
  先怀疑格式选错了，或者那本来就**不是**编码过的数据（比如它其实是密文）。

### `uuid`

- 生成的是 v4（随机）。**每次调用结果都不同**，所以它不能当幂等键或稳定标识。
- 要"同一个东西每次算出来都一样"的标识，用 `hash`。

### `time`

- **不传 `value` 就是当前时间** —— 想知道"今天几号"直接调它，不要猜。
- `value` 可以给 ISO 字符串、Unix 秒（10 位）、Unix 毫秒（13 位），
  或 `"2024-01-01 10:00"` 这类写法。它返回五种表示，按需取用。
- 它给的是**运行这个应用的那台机器**的本地时间。用户在其他时区时，
  本地时间与他的预期可能差几小时 —— 跨时区的事要说清是哪个时区。

## 一个组合用法

"这两个文件内容一样吗" —— 不要读两份全文再逐字比对（那会占满上下文）：

1. 分别 `read` 出来（如果本来就大，这一步就跑不掉）；
2. 各算一次 `hash`；
3. 比哈希。

反过来，"这段 base64 是不是某个已知内容的编码"也可以走同一条路。
