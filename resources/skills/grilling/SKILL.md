# 拷问（Grilling）

对用户进行**不留情面的追问**，直到双方对这件事的理解完全一致。

把这件事画成一棵**决策树**：每一个决定都会分叉出挂在它下面的决定。

## 一轮一轮地推进

按**轮次**推进这棵树。**前沿**（frontier）指的是：所有前置条件都已经定下来、
**现在就能问、不必猜测还没听到的答案**的那些决策。

**一整轮一次问完**：把当前前沿上的问题编号列出，每个都附上**你推荐的答案**。
然后**停下来等用户回答**，再进行下一轮。

一轮的格式：

```
❓ **Q1** — **<问题标题>**：<问题正文，可以多段，可以给出多个选项>

➡️ <你推荐的答案>

---

❓ **Q2** — **<问题标题>**：<问题正文>

➡️ <你推荐的答案>
```

**给推荐答案不是可选项。** 让用户在空白里凭空想，是把你的活推给他 ——
你已经有足够的上下文给出一个像样的默认选择。他可以不同意，但得有个东西可以反对。

## 每轮都会重塑这棵树

用户每一轮的回答都会改变树的形状：定下来的决策把前沿**向外推**，
解锁那些原本依赖它们的问题。重新计算前沿，再问下一轮。

**一个问题的答案如果依赖本轮另一个还没答的问题，它属于「后面的轮次」，不属于这一轮。**
把这种问题混进来，用户就得先猜一个答案才能回答另一个。

## 找事实是你的活，从来不是用户的

当前沿上的问题需要环境里的事实（文件、命令、依赖版本、现有实现），
**派一个子智能体去找**（explorer 就是干这个的）；凡是你能自己查的，不要问用户。

**但不要为它阻塞**：一个正在跑的探索是一个「尚未定下来的前置条件」，
所以**只有它下游的问题**需要等它回报 —— 前沿上其余的问题现在就问。

**决策才是用户的**：每一个都摆到他面前，然后等。

## 什么时候算完

**前沿空了就算完**：树的每个分支都走到了，没有任何东西是被默默假设掉的。

在用户确认「我们已经达成共识」之前，**不要动手做**这件事。
