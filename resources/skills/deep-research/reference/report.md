# 报告格式

`REPORT.md` 由你**一个人一次写成**。输入是 `brief.md` + 全部 `findings/*.md`。

**写作期间不要再搜索**：某个章节缺证据时，**把缺口写出来**，不要凭记忆补上。

## 结构

```markdown
# <标题：精炼后的调研问题>

> 生成于 <日期> · 深度：<档位> · <N> 个来源 · 工作区：research/<slug>/

## 结论摘要
5–10 条要点。**每条都带引用 [n]。** 只读这一段的人也应该拿到可用的结论。

## 背景与范围
2–4 句，来自 brief.md：问题、边界、做了哪些假设。

## <正文各节 —— 按主题组织，不要按子智能体/角度组织>
跨 findings 文件综合；合并重复的论断，把分歧摆出来。
- 行内引用："……在 2025 年增长了 40% [3][7]。"
- 冲突写法："来源 A（2026-03）报告 X [2]，而 B（2025-11）称 Y [5]；
  A 更新且更原始。"
- 标记：[单一来源] 用于只有一条引用的论断；[推测] 用于超出证据的推断。

## 对比表（主题涉及多个可选方案时）
| 方案 | <任务书里的关键维度> | 来源 |

## 未决问题
第 4 阶段没查掉的缺口，以及证据无法定论的部分。

## Sources
[1] <标题> — <URL>（发布于 <日期>，访问于 <今天>）
[2] ...
```

## 规则

- 每个 `[n]` 都必须能落到一个 Sources 条目，**且那个 URL 出现在某个 findings 文件里**。
  **绝不凭记忆引用**；
- 来源按**首次出现顺序**编号；跨 findings 文件去重 URL；
- 报告语言跟随用户的语言；技术术语与引文保留原文；
- 篇幅**与证据量相称，不要注水**。quick ≈ 1–2 页，standard ≈ 3–5 页，deep ≈ 5–10 页；
- 优先信息密度：实体、确切数字、日期、版本号 —— 而不是填充性文字。

## 批判性复读（仅 deep 档）

初稿写完后再读一遍，**把自己当成敌意的审稿人**，就地修：

1. 有没有该带引用却没带的论断？
2. 有没有哪个 `[n]` 的来源其实**并不支持**那句话？
3. 有没有哪一节**完全依赖**比任务书时间范围更旧的来源？
4. **最强的反方论点**有没有被呈现？
5. 结论摘要与正文一致吗？
