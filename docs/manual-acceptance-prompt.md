# Oint 手动验收提示词

启动软件、配置可用模型并选择一个工作目录后，在新聊天中粘贴下面的内容。测试只写自己创建的验收目录；需要授权时由你在界面操作。

```text
请对当前 Oint 做一轮真实的功能验收。必须实际调用工具，不要把已有测试报告或推测当成通过。

先在当前工作目录创建一个独立的 oint-acceptance-日期时间 目录。所有测试文件只能写在该目录；不要修改项目源码、设置、其他文件或安装任何依赖。

1. 用待办工具建立验收清单，并在每项实际完成后更新状态。调用一次 ask_user，让我选择“继续全部测试”或“仅测试本地功能”，收到答复后再继续。
2. 用文件工具创建两个小文本文件，分别写入不同内容；实际读取、搜索、修改其中一个，再读回确认。保留这些文件供我检查。
3. 如果已启用系统 toolkit 插件，调用它的哈希工具计算字符串 abc 的 SHA-256，预期为 ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad。再调用一个编码或 UUID 工具并检查结果。工具不存在时标“未配置”，不要以 shell 代替并宣称插件通过。
4. 使用 Task 同时派发两个只读子智能体，分别读取并总结刚才的两个文件。派发后主会话继续做下一项，不要立即阻塞等待；最后通过 TaskList/TaskWait 读取真实结果，核对两份报告是否对应正确文件。
5. 用后台作业工具启动一个约 10 秒后打印 BG_OK 的简单 Node 命令。记录 job id，查询状态和输出，确认它最终退出并保留输出。不要用前台 bash 冒充后台作业。如果环境缺少 Node，明确记为环境限制。
6. 仅当我选择全部测试且当前有已配置的 MCP 时，执行一次无副作用的只读调用，并说明服务器与工具名称；没有配置则记“未配置”，不要安装服务器或索要密钥。
7. 将真实结果写入验收目录下的 ACCEPTANCE.md，逐项列出“通过 / 失败 / 未配置或环境限制”、工具返回的证据和产物路径。列出所有子任务及作业的最终状态，不能把仍运行中的工作记成通过。

完成后告诉我需要手动观察的界面现象：待办、提问卡、并行子智能体卡、后台输出、插件工具结果及用量。最后停下来，给我三个后续操作：关闭重开查看持久化；在消息处创建分支查看待办和附件；停用插件或切换项目确认旧界面权限失效。不要声称你已自动验证这些手动操作。
```

建议补充检查：发送含附件的消息后创建分支，再删除源聊天，验证独立分支仍可读附件；在审批或长时间等待期间点击停止，确认不会随后执行已取消操作。崩溃恢复测试中的任意 shell 作业应被明确标记中断，不应自动重复执行命令。
